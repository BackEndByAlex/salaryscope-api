# Prisma Folder

This folder controls everything related to the database structure and data.

---

## Files

### `schema.prisma`
The blueprint of the database. Defines what tables exist and what columns they have.
Every time you change this file you need to run a migration to apply the changes.
**Never delete this — the entire app depends on it.**

### `migrations/`
Auto-generated by Prisma. Contains the SQL that was used to create and update the tables.
When the app is deployed somewhere new, Prisma runs these files to rebuild the database structure from scratch.
**Never delete this — without it the database cannot be recreated.**

### `seed.js`
A one-time script that reads the CSV files in `data/` and inserts ~23,000 salary records into the database.
Run it once after the database is created. Safe to re-run (uses `skipDuplicates`).

The `data/` folder is not committed to git. Download the CSV files manually and place them there before seeding:
- `jobs_in_data.csv` — [Jobs in Data (2020–2023)](https://www.kaggle.com/datasets/hummaamqaasim/jobs-in-data?resource=download)
- `jobs_in_data_2024.csv` — [Jobs and Salaries in Data Field 2024](https://www.kaggle.com/datasets/murilozangari/jobs-and-salaries-in-data-field-2024)

## Common commands

```bash
# Apply schema changes to the database (development)
npx prisma migrate dev --name describe_your_change

# Recreate the Prisma client after a schema change
npx prisma generate

# Fill the database with data from the CSV files
node prisma/seed.js

# Open a browser UI to browse the database
npx prisma studio

# Apply migrations in production (does not prompt, safe for CI/Docker)
npx prisma migrate deploy
```

## Where is the data?

The data lives inside the PostgreSQL container managed by Docker.
The `postgres_data` volume in `docker-compose.yml` keeps it persistent across restarts.

To start the database locally:
```bash
docker compose up -d postgres
```
